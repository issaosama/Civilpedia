# مخطط JSON للمسودة (Draft JSON Schema) — دليل باللغة العربية

## ما هو Draft JSON؟

Draft JSON هو تنسيق **مصدر الحقيقة** الجديد لمحتوى Civilpedia. كل موضوع (Topic) يمثله ملف `.draft.json` واحد. هذا التنسيق صُمم ليكون سهل القراءة والتحرير من قبل مؤلفي المحتوى، مع الحفاظ على هيكل منظم يمكن التحقق منه آلياً.

## لماذا أصبح المصدر الأساسي؟

كانت المنصة سابقاً تعتمد على جداول Excel و Google Sheets كطريقة لإدخال المحتوى، مع محول (converter) يحولها إلى ملف `catalog.json` الذي يقرأه التطبيق. هذه الطريقة كانت:

- صعبة الصيانة عندما يزداد عدد المواضيع
- عرضة للأخطاء في تنسيق الخلايا والأعمدة
- غير مهيأة لسير عمل التحرير والمراجعة (review workflow)
- لا تدعم ميزات حسابات المستخدمين والأدوار (roles) مستقبلاً

لهذا السبب، انتقلنا إلى تنسيق JSON لكل موضوع على حدة، مما يسهل التحرير والمراجعة والتصدير.

## كل موضوع = ملف JSON واحد

كل موضوع في Civilpedia سيكون له ملف منفصل باسم `[topic-id].draft.json` داخل مجلد `draft_jsons/`.

مثال:
- `iraqi-tiles-types.draft.json`
- `slump-test.draft.json`
- `concrete-curing.draft.json`

## الأقسام (Sections)

كل موضوع يحتوي على قائمة من **الأقسام**. كل قسم يمثل جزءاً مستقلاً من المحتوى، مثل:

- قسم عام (General) — جداول، مقارنات، معلومات عامة
- قسم تنفيذي (Execution) — خطوات العمل بالتسلسل
- قسم فحص (Inspection) — نقاط التفتيش ومعايير القبول
- قسم سلامة (Safety) — ملاحظات السلامة والمخاطر
- قسم معدات (Equipment) — الأدوات المطلوبة
- قسم مراجع كود (Code Reference) — معايير ومواصفات فنية

كل قسم يحتوي على:
- `id` معرّف فريد (مثل `tile-application`)
- `title` عنوان القسم بالعربية
- `type` نوع القسم
- `order` ترتيب العرض
- `blocks` مصفوفة من الكتل المحتوىية

## الكتل (Blocks)

داخل كل قسم توجد **كتل محتوىية** (Blocks). كل كتلة تمثل وحدة محتوى صغيرة ومستقلة. أنواع الكتل المدعومة:

- **نص (text)**: فقرة نصية عادية، أو ملاحظة، أو تحذير
- **خطوة تنفيذية (execution_step)**: خطوة مرقمة ضمن إجراء عمل
- **ملاحظة سلامة (safety_note)**: تعليمات وقائية مع مستوى الخطورة
- **جدول (table)**: جدول بيانات بعناوين وأعمدة وصفوف
- **قائمة فحص (checklist)**: نقاط يجب التأكد منها
- **نقطة فحص (inspection_point)**: معيار فحص مع طريقة القياس وحدود القبول
- **مرجع كود (code_reference)**: إشارة إلى كود أو مواصفة فنية
- **معدات (equipment)**: قائمة بالأدوات المطلوبة
- **صورة (image)**: صورة توضيحية

كل كتلة تحتوي على `type` (نوع الكتلة) و `order` (ترتيب العرض داخل القسم).

## حقول المراجعة والموافقة (Review / Status)

كل موضوع يحتوي على قسم `review` مخصص لإدارة دورة حياة المحتوى:

- **حالة المسودة**: `draft` (قيد التحرير)، `in_review` (قيد المراجعة)، `changes_requested` (مطلوب تعديلات)، `approved` (معتمد)، `rejected` (مرفوض)
- **حالة الموضوع**: `draft`، `review`، `approved`، `published`، `archived`
- هذه الحقول تمهد لدعم حسابات المحررين والمراجعين والموافقات مستقبلاً.

## الاستعداد للمستقبل

### حسابات المحررين والمراجعين

الحقول مثل `createdBy` و `updatedBy` و `reviewedBy` موجودة الآن (اختيارية) لتدعم مستقبلاً ربط المحتوى بحسابات المستخدمين وأدوارهم (Editor، Reviewer، Admin).

### قاعدة بيانات سحابية (Supabase / Firebase)

تنسيق Draft JSON مهيّأ للتصدير إلى قواعد البيانات السحابية:

- كل موضوع = سجل (row) في جدول topics
- كل قسم = سجل في جدول sections مع `topic_id` كـ foreign key
- كل كتلة = سجل في جدول blocks مع `section_id` كـ foreign key
- سهولة ربط المحتوى بالحسابات والأدوار والصلاحيات

## الفرق بين Draft JSON و App-ready JSON

| الخاصية | Draft JSON | JSON التطبيق (catalog.json) |
|----------|------------|-----------------------------|
| النطاق | ملف واحد لكل موضوع | جميع المواضيع في ملف واحد |
| البنية | أقسام وكتل متداخلة | جداول مسطحة (flat maps) معرفة بالمعرّفات |
| اللغات | نصوص ثنائية (عربي/إنجليزي) معاً | نصوص مفردة لكل حقل حسب اللغة |
| الحقول التحريرية | `_meta`، `review`، بيانات وصفية غنية | بيانات دنيا فقط |
| يقرأه التطبيق | لا (ليس بعد) | نعم (التنسيق الحالي) |
| قابل للتحرير البشري | نعم، صمم لهذا | لا، محسّن للقراءة الآلية |

## ملاحظة مهمة

**تطبيق Flutter لا يقرأ Draft JSON مباشرة بعد.** التنسيق الحالي للتطبيق هو `catalog.json`. مسار التصدير من Draft JSON إلى `catalog.json` سيبنى في المراحل القادمة.

## مثال سريع

```json
{
  "_meta": {
    "schemaVersion": "1.0.0",
    "version": 1
  },
  "topic": {
    "id": "iraqi-tiles-types",
    "titleAr": "الكاشي وأنواع البلاط في السوق العراقي",
    "categoryId": "finishing"
  },
  "sections": [
    {
      "id": "tile-application",
      "title": "خطوات التبليط التنفيذية",
      "type": "execution",
      "order": 2,
      "blocks": [
        {
          "type": "execution_step",
          "order": 1,
          "stepNumber": 1,
          "description": { "ar": "تجهيز السطح..." }
        }
      ]
    }
  ],
  "review": {
    "status": "in_review"
  }
}
```
