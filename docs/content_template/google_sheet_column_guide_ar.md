# دليل أعمدة جداول المحتوى الهندسي

## مقدمة

نظام المحتوى في Civilpedia يعتمد على 8 جداول بيانات (CSV) مترابطة لتخزين المحتوى الهندسي.
هذا الدليل يشرح دور كل جدول وأهم الأعمدة فيه.

---

## 1. Topics — الموضوعات

**الدور:** الجدول الرئيسي. كل صف يمثل موضوعاً هندسياً واحداً في التطبيق.

| العمود | الشرح |
|--------|-------|
| `topicId` | معرّف فريد للموضوع بالإنكليزية بدون مسافات. هذا المعرف يربط كل بيانات الموضوع عبر جميع الجداول الأخرى. |
| `titleAr` | عنوان الموضوع بالعربية. يظهر في قائمة المواضيع وفي أعلى شاشة الموضوع. |
| `categoryId` | تصنيف الموضوع: concrete, steel, soil, asphalt, general, finishing |
| `summary` | جملة مختصرة تصف الموضوع. تظهر في بطاقة الموضوع تحت العنوان. |
| `simpleExplanation` | شرح مبسط جداً للموضوع يظهر في أعلى المقال. |
| `beforeWork` / `duringWork` / `afterWork` | نصوص طويلة تصف مراحل العمل. يستخدمها التطبيق لتقسيم المحتوى إلى أقسام. |
| `siteNotes` / `codeNotes` | ملاحظات موقعية ومراجع كود تظهر للمستخدم في قسم الأهمية الهندسية. |
| `reportWording` | صياغة جاهزة يمكن نسخها (Copy) مباشرة للتقرير النهائي. |
| `level` | مستوى الموضوع: basic, intermediate, advanced |
| `status` | حالة سير العمل: Draft > Engineering Review > Approved > Ready for App |

---

## 2. Sections — الأقسام

**الدور:** تقسيم كل موضوع إلى أقسام فرعية. كل موضوع يحتوي على عدة أقسام.

| العمود | الشرح |
|--------|-------|
| `topicId` | معرف الموضوع الذي ينتمي إليه القسم. |
| `sectionId` | معرّف فريد للقسم. يستخدم لربط البلوكات بهذا القسم. |
| `order` | ترتيب القسم في المقال (يبدأ من 1). |
| `title` | عنوان القسم بالعربية. يظهر كعنوان فرعي. |
| `type` | نوع القسم: execution, inspection, safety, equipment, codeReference, general |

> النوع `general` يُستخدم للأقسام التي لا تناسب الأنواع الأخرى (مثل جداول المقارنة).

---

## 3. Blocks — بلوكات المحتوى

**الدور:** أصغر وحدة محتوى داخل كل قسم. كل بلوك يمثل فقرة، صورة، جدول، خطوة تنفيذ، نقطة فحص، إلخ.

**أهم 3 أعمدة تحدد البنية:**

| العمود | الشرح |
|--------|-------|
| `sectionId` | معرف القسم الذي ينتمي إليه البلوك. |
| `order` | ترتيب البلوك داخل القسم. |
| `type` | نوع البلوك. هذا الحقل يحدد أي الأعمدة الأخرى يجب ملؤها. |

**أنواع البلوكات والأعمدة المرتبطة بكل نوع:**

| النوع | الأعمدة المطلوبة |
|-------|-----------------|
| `text` | `text_content`, `text_variant` |
| `execution_step` | `step_number`, `step_description`, `step_notes` (اختياري) |
| `inspection_point` | `point_criteria`, `point_tolerance`, `point_method`, `point_critical` |
| `safety_note` | `safety_message`, `safety_severity` |
| `table` | `table_caption` (اختياري) — البيانات تأتي من جدول TableRows |
| `checklist` | `checklist_title` (اختياري) — البيانات تأتي من جدول ChecklistItems |
| `equipment` | `equipment_title` — البيانات تأتي من جدول EquipmentItems |
| `image` | `image_url`, `image_caption` (اختياري) |
| `code_reference` | `code_code`, `code_section`, `code_title`, `code_description` |

---

## 4. TableRows — صفوف الجداول

**الدور:** تخزين بيانات الجداول (صفوف وأعمدة) التي تظهر داخل المقال.

| العمود | الشرح |
|--------|-------|
| `sectionId` | معرف القسم الذي يوجد به الجدول. |
| `blockOrder` | ترتيب البلوك (نفس قيمة `order` في blocks.csv) لربط الصفوف ببلوك الجدول. |
| `rowOrder` | ترتيب الصف داخل الجدول. |
| `headers` | رؤوس الأعمدة مفصولة بفواصل. إذا كانت موجودة هنا، ستستخدم بدلاً من `table_headers` في blocks.csv. |
| `cells` | قيم الصف مفصولة بفواصل. |

---

## 5. ChecklistItems — بنود قوائم الفحص

**الدور:** تخزين عناصر قوائم الفحص التي تظهر داخل المقال.

| العمود | الشرح |
|--------|-------|
| `sectionId` | معرف القسم. |
| `blockOrder` | ترتيب البلوك لربط البنود ببلوك القائمة. |
| `itemId` | معرّف فريد للبند. |
| `itemText` | نص بند الفحص بالعربية. |
| `isRequired` | TRUE إذا البند إلزامي، FALSE إذا اختياري. |

---

## 6. AcceptReject — معايير القبول والرفض

**الدور:** قائمة بمعايير الفحص والقبول التي تظهر في قسم الفحص.

| العمود | الشرح |
|--------|-------|
| `topicId` | معرف الموضوع. |
| `criteriaAr` | معيار القبول أو الفحص بالعربية. |
| `acceptanceLimitAr` | حد القبول المسموح. |
| `methodAr` | طريقة الفحص أو القياس. |
| `isCritical` | TRUE إذا كان المعيار حرجاً (يظهر باللون الأحمر). |

---

## 7. CommonMistakes — الأخطاء الشائعة

**الدور:** قائمة بالأخطاء الشائعة التي يرتكبها المهندسون في الموقع، مع تحذيرات.

| العمود | الشرح |
|--------|-------|
| `topicId` | معرف الموضوع. |
| `mistakeAr` | وصف الخطأ الشائع بالعربية. يظهر في قسم الأخطاء الشائعة. |
| `mistakeEn` | وصف الخطأ بالإنكليزية. |

---

## 8. EquipmentItems — المعدات والأدوات

**الدور:** قائمة بالمعدات والأدوات المطلوبة لتنفيذ العمل.

| العمود | الشرح |
|--------|-------|
| `sectionId` | معرف القسم. |
| `blockOrder` | ترتيب البلوك. |
| `name` | اسم الأداة أو المعدة. |
| `purpose` | الغرض من الاستخدام (يظهر في التطبيق). |
| `specification` | المواصفات الفنية (يظهر أيضاً). |

---

## كيف تربط البيانات بين الجداول؟

مفتاح الربط الأساسي هو **`topicId`** — معرف الموضوع الذي يتكرر في Topics، Sections، AcceptReject، CommonMistakes.

مفتاح الربط الثاني هو **`sectionId`** — معرف القسم الذي يربط Sections مع Blocks، ChecklistItems، TableRows، EquipmentItems.

مفتاح الربط الثالث هو **`blockOrder`** — ترتيب البلوك الذي يربط Blocks مع TableRows، ChecklistItems، EquipmentItems.

```
Topics  ←── topicId ──→ Sections, AcceptReject, CommonMistakes
Sections ←── sectionId ──→ Blocks
Blocks ←── blockOrder ──→ TableRows, ChecklistItems, EquipmentItems
```

## ماذا لو كان الموضوع لا يحتاج إلى جدول أو صور؟

اترك الأعمدة غير المطلوبة **فارغة** تماماً:

- إذا كان الموضوع لا يحتاج جدول → لا تضف بلوك من نوع `table` في blocks.csv.
- إذا كان الموضوع لا يحتاج صور → اترك `image_url` فارغاً.
- إذا كان الموضوع لا يحتاج معدات → لا تضف بلوك من نوع `equipment`.
- إذا كان الموضوع لا يحتاج قائمة فحص → لا تضف بلوك من نوع `checklist`.
- الأعمدة الاختيارية في نفس البلوك: اتركها فارغة (مثلاً: `step_notes`، `image_caption`).

> **لا تكتب "NULL" أو "N/A" أو مسافة.** الفارغ = لا شيء = يتجاهله المحول البرمجي.

## سير العمل: من Google Sheet إلى التطبيق

```
المهندس → يملأ Google Sheet (القالب الموجه)
    ↓
المراجع → يراجع البيانات هندسياً
    ↓
المطور → يصدر كل ورقة كملف CSV منفصل
    ↓
المطور → ينسخ ملفات CSV إلى مجلد content_source/
    ↓
المطور → يشغل أداة التحويل: dart run bin/convert.dart content_source ../../assets/encyclopedia/catalog.json
    ↓
المطور → يراجع التغييرات في catalog.json عبر git diff
    ↓
المطور → يدمج التغييرات في الفرع الرئيسي
    ↓
التطبيق → يعرض المحتوى تلقائياً بعد البناء التالي
```

### ملاحظة مهمة عن القالب الموجه (Guided Template)

القالب الموجه يحتوي على صف شرح بالعربية فوق صف الرؤوس. هذا الصف مخصص للمساعدة أثناء التحرير فقط.
**لا تصدر القالب الموجه مباشرة إلى CSV** بدون إزالة صف الشرح أولاً.

استخدم القالب الإنتاجي (Production Template) للتصدير — صف الرؤوس فيه هو الصف الأول مباشرة.
