2.2 lib/core/widgets/remote_data_notice.dart  (NEW)
======================================================================
- RemoteDataNotice: typed remote-state notice; NEVER exposes raw errors.
- RemoteDataCause (typed enum): offline, timeout, serviceUnavailable,
  malformed, permissionDenied, authRestricted, invalidState, conflict,

  NEVER queues work, has no mutation API.
- Semantic labels per mode; works RTL/LTR, light/dark, narrow screens.

2.3 lib/core/network/reconnect_generation_gate.dart  (NEW)
======================================================================
- ReconnectGenerationGate: pure generation-claim tracker used to make a
  reconnect retry authoritative once per transport recovery.
- Pure logic only: NO Timer, NO Future, NO ConnectivityProvider, NO streams.
- bind(connectedGeneration): records the claimable generation.
- claimCurrentGeneration(gen): returns true only for the CURRENT generation,
  exactly once; newer generations are rejected until bind updates the current
  value; older generations are never claimable; non-positive and UNKNOWN
  generations are never claimable.
- Failed reads do NOT reopen an old (already-settled) generation.
- dispose(): prevents further claims (no timer/future lifecycle concerns).

APPENDIX A — CORRECTION NOTE (append-only; historical content above is
NOT rewritten. Filed during the P2-A localization correction pass.)
======================================================================
CORRECTION: Section 2.3 wording ("newer generations are rejected until
bind updates the current value") mis-describes the frozen ReconnectGenerationGate
semantics. The gate implementation (lib/core/network/reconnect_generation_gate.dart)
and its test suite were already correct; only the prose was wrong. The frozen
semantics verified by the gate now read:

- The initial generation is recorded at bind().
- Zero and negative generations are rejected (generation <= 0 is never claimable).
- The same generation is rejected (already handled; claimed once only).
- An older generation is rejected (never claimable after a newer one).
- Every newer positive generation may be claimed once; each successful claim
  advances the handled baseline, so consecutive newer generations are each
  claimable without re-binding.
- A failed external read does NOT reopen an already-claimed generation
  (the gate is pure bookkeeping; it never un-claims on read failure).
- No re-bind is required before claiming a later newer generation
  (bind is only for initial/onboarding synchronization).
